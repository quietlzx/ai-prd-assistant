# PRD 模板

## 文档头部

- 产品名称
- 产品版本
- PRD 版本
- 运行 ID
- 框架版本
- 流水线状态
- 审核状态
- 时间戳
- 输入摘要

## 必需章节

### 1. 产品概述

描述产品定位、目标结果和强制边界。不得写入未经证实的信息。

### 2. 产品目标

写明可量化目标和非目标。

### 3. 用户与场景

使用具体用户和具体工作流。推断出的用户或场景必须标记 `[推断]`。

### 4. 范围边界

分别列出范围内和范围外行为。

### 5. 功能能力

每个能力必须包含：

- 用户目标
- 输入
- 处理规则
- 输出
- 失败状态
- 边界条件
- 验收标准

AI 产品必须显式覆盖事实依据、引用、权限过滤、拒答、人工审核、失败关闭和数据生命周期事件。

### 6. 非功能需求

定义性能、安全、隐私、可用性、可观测性、可审计性、权限、回滚和数据保留要求。

### 7. 量化质量目标

明确统计分母、抽样规则和评测来源。禁止只写“准确率高”等无法验收的描述。

### 8. 生命周期行为

描述更新、删除、下线、撤权、索引失效、缓存失效和历史引用行为。

### 9. 验收场景

覆盖成功、拒答、阻断、人工审核、权限变化、删除、过期文档、模型故障和回滚。

### 10. AI 风险

使用风险分类文档中的固定字段。

### 11. 人工审核门禁

记录 `pipeline_status`、`review_state`、审核输入、审核决策和进入报告组装的条件。

### 12. 报告组装

要求从已批准版本生成 Markdown 和单文件 HTML 产物。

### 附录 A：待确认事项清单

每个未决事项使用以下格式：

```text
Gxx
当前默认：
决策人：
Gate 影响：

| 方案 | 业务影响 | 开发影响 |
|---|---|---|
| A | ... | ... |
| B | ... | ... |

推荐方案：
状态：[待确认:Gxx]
```

主文档中不得保留未编号的 `[待确认]` 标记。

## 能力写法

当表格难以阅读时，使用以下结构：

```markdown
#### F1 能力名称

- 用户目标：
- 输入：
- 处理规则：
- 输出：
- 失败状态：
- 边界条件：
- 验收标准：
```
